# Agent Brain development rules

- Keep the registry read-only with respect to external skill and project
  sources unless the user explicitly requests a migration.
- Generated files live under `data/`, `reports/`, and `views/`. `config/`, `domains/`, `projects/`, and `workflows/` are a user's private registry: git-ignored, absent from a fresh clone. Tracked sources include `brain.py`, `core/`, `defaults/`, `web/`, `desktop/`, `electron/`, and `claude-mod/`.
- Do not make a skill global merely because a runtime mounts it globally.
- Preserve symlinks and record both mount path and resolved source path.
- Never print environment variables, tokens, or skill file bodies into the
  generated inventory.
- The visual dashboard must be generated from the same inventory used by the
  CLI router.
- The Electron renderer must remain sandboxed. Expose only narrow typed actions
  through the preload bridge; never expose raw `ipcRenderer`, Node.js, a shell,
  or arbitrary filesystem access.
- The desktop app and the Claude Code mod (`claude-mod/`) are views over the canonical `brain.py` resolver, not second routing implementations. The mod gets data only from `bin/brain ... --json`; its only writes are `brain use <domain> --settings local --cwd <folder>` and `brain skill off <name> --settings local --cwd <folder>`, run only after a confirm screen shows the exact command and the person presses "Выполнить". Session start only sets the status line and a stale-profile toast and adds nothing to the model context; the pane opens only on `/brain`.
- Run `python3 -m unittest discover -s tests -v`, `bin/brain validate`, and
  `bin/brain build` after changing routing or generation code. Run `npm test`
  and `npm run package` after changing the Electron application.

## Claude Code mod (`claude-mod/`)

- After changing `claude-mod/`, run from the repo root: `claude plugin test claude-mod && claude plugin validate claude-mod && tsc -p claude-mod` (all tests pass, validate ends with "Validation passed", tsc prints nothing). `claude plugin test` runs every `*.test.ts(x)` in the mod folder; one file cannot be run alone. Use `tsc` from PATH (5.8.3), not `node_modules/.bin/tsc` (5.4.5). `claude-mod/.claude-plugin/types/` is git-ignored and written by Claude Code when it loads the mod, so `tsc` fails in a fresh clone until then.
- The first nine tests in `claude-mod/tests/brain.test.tsx` (everything above `const META_INSPECT`) are the owner's decisions: if one fails, change the code, never the test. They press `apply`, `cancel`, `confirm`, `off-<skill>`, `tab-calls` and pin the write argv from the mod contract, the status line `Brain: <area> · /brain`, and the strings "Видны, но вне этой области", "Готово", "Не вышло: <text>", "Brain не ответил: ...", "не найден brain: <path>", "обновить его: brain use <domain>", "settings.local.json" on the confirm screen, and "правил N, выключено N; MCP-серверов N; агентов N; файлов инструкций N" in one `Text`. Also do not rename the keys `reload`, `tab-skills`, `tab-dupes`, `tab-advice`; no test presses `tab-skills`, so nothing but this line protects it. With at most five skills outside the area, `off-<skill>` must be on screen right after the pane opens.
- `claude-mod/hooks/`: `view.ts` turns `brain ... --json` into `BrainView` (data only); `charts.ts` has the number and color functions (pure, no JSX); `panel.tsx` has the render pieces, called as plain functions with `ui` first (`{ShareBar(ui, view)}`), not as tags; `register.tsx` has the hooks, `load`/`execute` and the state atoms. New state needs an `atom({ plugin: 'agent-brain', key })` in `register.tsx` and a field in `PluginState['agent-brain']` in `claude-mod/types/index.d.ts`. Pane tests stub `process.run` (see `brainWorld` in `claude-mod/tests/brain.test.tsx`) and mount the pane on both `terminal` and `desktop`.
- Build the pane only from `Box`, `Text` and `Button`: it is drawn on terminal and desktop, `Svg` is not in the terminal table, `Raster` and `Image` exist only in the terminal (a test asserts none are drawn). Bars are `Box` with a hex `backgroundColor`; `width` must be whole percents (`percentShares`, `percentOfMax`): a fractional `'33.3%'` is rejected by the engine and the whole pane stops drawing. `Button` takes no color, width or background; `Box` has no `flexBasis`, `maxWidth` or `overflow: 'scroll'`; the engine scrolls the pane body. In a wrapping row use `columnGap`, not `gap`: `gap` also adds a blank line between the wrapped rows. Tests see props (`backgroundColor`, `width`) through `ui.findAll({ type: 'Box' })`, not the real layout or colors, so check those by eye.
- The duplicate redirect (`skill_preferences`) and the skill-call counter live in the `tool.call` hook for the `Skill` tool in `claude-mod/hooks/register.tsx`, never in `skill.prompt`: under managed settings the built-in security plugin bypasses a user mod's `skill.prompt`. A skill typed as `/name` never reaches the Skill tool, so `prompt.submit` counts it and nothing redirects it.
- The mod runs `<mod folder>/../bin/brain`, or the path in `AGENT_BRAIN_BIN` when set. The copy Claude Code installs into `~/.claude/plugins/cache/agent-brain/agent-brain/<version>` has no `bin/brain` beside it, so a session that loads that copy shows "не найден brain: <path>" until `AGENT_BRAIN_BIN` is set. Sessions that load the cached copy keep the old code until the plugin is updated: after editing the mod, bump `version` in `claude-mod/.claude-plugin/plugin.json`, run `claude plugin update agent-brain@agent-brain`, and open a new session.
- `bin/brain use <domain>` without `--settings local --cwd <folder>` writes `~/.claude/settings.json` and changes every session: while developing use `--dry-run` or the local form (`skill on|off` already defaults to local). `brain inspect`, `use ... --dry-run` and `status` rebuild the git-ignored `data/`, `reports/` and `views/`, so changes there are expected. A checkout with `config/brain.json` is its own registry (`bin/brain --help` prints which one). The mod tests stub `brain` and need no registry; in a fresh clone a live `brain use <domain> --dry-run` fails with "Unknown domain".
- CI (`.github/workflows/ci.yml`) never runs the mod checks, so run them yourself. `npm run test:public` scans tracked and untracked-not-ignored text files (`.md`, `.json`, `.cjs`, `.py`, ...; not `.ts` or `.tsx`) for absolute home paths, token prefixes, the developer's username and private ticket or agent markers, so `AGENTS.md` and `README.md` must stay free of them. Untracked, not git-ignored folders such as `.autopilot/` or `.claude/` are scanned too, and `git add -A` would stage them. Stage by explicit path.
